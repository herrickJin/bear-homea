## 产品定位

「熊熊之家」是给装修中的小两口使用的工具，把装修灵感、选购比较和后续预算管理集中在一起，并通过 AI 帮忙收集、整理装修资料。

它的主要使用场景是：看到喜欢的装修方案时收进笔记库，逛店或网购时记下型号与报价，逐步形成设计和购买决策。

## 功能分工与当前状态

| 模块 | 产品职责 | 当前实现 |
| --- | --- | --- |
| 小家 | 首页入口；具体概览内容尚未实现 | 工具入口页，挂「户型平面」卡片 |
| 笔记库 | 保存装修链接、截图和自己的想法，按空间分类，追加讨论备注 | 已有前端页面与后端接口 |
| 清单（装修准备） | 按房间组织准备项与候选，记录型号、报价、渠道与状态，支持比较与购买决策 | 页面已实现，数据已接服务端同步 |
| 户型工具 | 还原原始建筑测量图，查看墙、房间与面积 | 第一版 SVG 已上线（2026-10-21） |
| 预算 | 承接实际花费与预算管理；具体功能尚未实现 | 占位页 |
| 我的 | 个人相关入口；具体功能尚未实现 | 占位页 |

三个核心概念的分工：**笔记是装修设计素材库，清单是购物决策账本，预算负责实际花费。**

导航只保留「笔记 / 清单」两项；小家、户型、预算、我的通过侧栏品牌位或首页卡片进入。

### 笔记库

- 支持粘贴分享文本并提取链接与标题，也能保存纯文字想法和附带截图。
- 支持分类筛选、搜索，以及分类新增、改名、排序和删除。
- 以图片瀑布流展示内容，点击卡片原地打开详情弹层。
- 详情支持查看摘要、修改用户要点与分类、追加或删除备注、打开原文及删除笔记。
- 配置 API 地址时走后端；未配置时使用内存 mock，后者不具备持久保存能力。
- 后端支持链接判重、异步抓取网页元信息和封面转存；Agent 可进一步写回标题、摘要和正文。

主要入口：`src/pages/inspiration/index.tsx`、`src/components/LinkDetailSheet.tsx`、`src/services/inspiration.ts`。

### 装修准备（清单）

- 一级是房间：全屋、客厅、餐厅、主卧、次卧、厨房、卫生间、阳台；房间内是扁平记录列表。
- 一条记录代表一个候选，字段包括名称、品类、价格、状态、备注、图片与链接。
- 状态为「候选」「已选定」「已买」。
- 候选支持多图（≤9 张）、设为封面、补充关键参数，参数可留空；对比只在主动选择 2–3 个同类候选时展开。
- 准备项按房间维护，可自定义增删；候选可关联到准备项或直接归入「待归类」。
- 记录可关联已有笔记，笔记本身仍保留在笔记库。
- **已接服务端**：`GET/PUT /api/preparation`，整份数据以单行 JSON 存 `preparation_state`，
  PUT 带 `revision` 乐观锁，冲突返回 409。前端 `usePreparationSync` 负责乐观更新、
  待同步草稿落本地 storage、冲突时保留草稿不覆盖，本地缓存仅作离线兜底。
- 未配置后端时回退内存 mock（无持久化）。

主要入口：`src/pages/record/Preparation.tsx`、`src/pages/record/usePreparationSync.ts`、
`src/services/preparation.ts`、`src/data/preparation.ts`。

### 户型工具

- 还原原始建筑测量图，不渲染方案家具。
- SVG 分层渲染：房间底色 → 墙段 → 门窗洞 → 房间名/面积 → 选中描边 → N↑ 朝向标。
- 墙数据用 GLB 直提的 72 段墙（含真实墙厚），`strokeWidth` 直接用毫米，任意缩放视觉正确。
- 9 个房间面积合计 108.54 ㎡，点选房间显示尺寸、面积、ID 与判定备注。
- 数据源在 `../archive/floorplan-source/`（GLB + ViewData + 123kanfang 墙线图 + 派生脚本）。

主要入口：`src/pages/floorplan/index.tsx`、`src/pages/floorplan/FloorplanSVG.tsx`、
`src/data/floorplan/`。细节见 `../.task-docs/18-floorplan-source-data.md`。

## 技术结构

### 前端：当前 `bear-home/` 项目

- Taro 4 + React 18 + TypeScript，同一套页面输出微信小程序和 H5。
- H5 适配手机、平板和电脑，使用 hash 路由。
- `Screen` 提供公共外壳：品牌侧栏、手机底部导航和页面标题区（桌面已去掉顶栏与面包屑）。
- 小程序使用自定义导航，并计算状态栏及胶囊安全空间。
- `src/styles/tokens.css` 定义设计变量，`DESIGN.md` 解释视觉规范。
- `src/services/` 隔离数据访问，页面通过服务层调用 API 或本地实现；未配置后端时逐函数回退 mock。
- `src/hooks/` 提供弹层进出动画与手势返回。

### 后端：相邻 `../server/` 项目

- Hono + SQLite（better-sqlite3），按单用户、单进程、自托管方式设计。
- 提供笔记、分类、备注、上传文件、装修准备、房间目录、AI 单次动作、旧施工记录与 AI 聊天接口。
- 通过 Bearer Token 鉴权，上传文件内容落盘，元数据保存于数据库。
- `services/preparation-state.ts` 是准备数据的唯一读写口，HTTP 路由与 AI 工具共用。
- 提供 MCP 接口，让外部 Agent 通过工具访问同一份数据。
- 包含 Docker Compose、Caddy、部署脚本与备份脚本。

## AI 与微信联动

项目采用两条 AI 通道：

1. **App 内实时助手**：后端 `/api/chat` 提供对话、工具调用、流式响应和会话存储；当前前端没有聊天界面。
2. **Hermes Agent**：独立容器中的 Agent 通过 MCP 操作后端，承担链接整理、网上研究和消息网关联动。

另有两条**单次、不落库**的 AI 接口，供前端在具体动作里就地调用：

- `POST /api/record-draft` —— 随手记 → 选购草稿，用户确认后才由前端保存。
- `POST /api/analyze` —— 候选 → 选购分析文本，预览与已保存状态视觉区分，确认后写入该候选。

两者共用 `TARO_APP_AI_BASE` 指向的地址。

部署任务文档记录了 Hermes 上线、微信通道接入，以及链接投喂和网上研究结果回存笔记的验证。此处将这些信息视为历史部署记录，本次未重新验证线上状态。部分任务索引和勾选状态落后于文档中的更新记录。

目标使用链路为：**App 或微信提供链接 → 服务端抓取或 Hermes 提取整理 → 标题、摘要和封面写回笔记 → App 查看和继续补充。**

研究技能位于 `../server/deploy/hermes/skills/bear-research/SKILL.md`，联动记录见 `../.task-docs/09-note-web-linkage.md`。

## 视觉方向

当前设计方向是「样板画廊 · 暖色签名」，并已加入瀑布流形态：

- 暖白背景，图片为主，常规内容区域以细分隔线和克制的层次呈现。
- 苔绿承担主要交互，小熊、胶带、蜂蜜黄与陶橘保留品牌记忆。
- 笔记列表与详情参考小红书的阅读和操作方式。
- 桌面与平板使用侧栏，手机使用底部导航。
- 笔记页与清单页在 `tokens.css` 共用中性白灰配色（`.page-inspiration` / `.page-record` 作用域覆盖），
  暖色签名留在壳层。

详细规则与局部例外以 `DESIGN.md` 和实际 token 定义为准。`DESIGN.md` 按时间顺序追加章节，
冲突处以后出现的章节为准（如 §19 覆盖 §12、§26 覆盖 §25）。

## 阅读项目时需要注意

- 后端 `entries` 仍保存旧施工记录模型（标题、正文、阶段、日期），应用侧从不写入也不展示；
  它只留在 MCP 工具面供 Hermes 使用，不在 App 聊天工具面里。
- 笔记未配置 API 时的 mock 为内存数据，与准备数据的「服务端 + 本地缓存」方式不同。
- 后端可以保存笔记全文 `content`，当前前端详情主要展示摘要，尚未渲染该全文字段。
- 户型工具的数据源在 `../archive/floorplan-source/`，其中 `floordata0.glb`（8.3MB）已入库，
  派生脚本可从它重新生成 `walls.json` / `rooms.json`。
- 预算、我的及 App 内 AI 对话界面，仍需后续产品设计与实现；
  「小家装修计划与 Agent 助理」已有设计稿（`docs/plans/global-renovation-plan.md`），尚未实施。
- 独立页面（不挂 `<Screen>`）没有 `.app-shell` 承载设计 token；H5 也没有 `<page>` 元素
  （根是 `div.taro_page`），所以 `tokens.css` 额外挂 `:root` 兜底。

整体判断：项目已从跨端骨架进入核心功能落地阶段，当前最完整的三块是装修笔记库、装修准备清单和户型工具；
AI 与微信联动为资料收集和整理提供扩展能力。下一个大块是「小家装修计划 + Agent 助理」，
前提是先收口 App 聊天工具面与 MCP 工具面的数据面差异。
