## 1. 户型与坐标基准

- 项目：城投南山长投·领峯 D143（参考方案平面图标注 "D1 4 3 / 三室两厅两卫"）
- 风格：意式·极意之境（123kanfang styleName=`Italian_1311`）
- 总尺寸：13.41 m × 11.38 m（GLB 场景外轮廓）。
  与 208.jpg 标注 13200×11340mm 差异 ~200 mm（墙厚公差），与用户自家尺寸图 13430×11360mm 差 ~20 mm（视为同源）。
- 单位：GLB 1 单位 = 10 mm；ViewData `Rooms[].Area` 直接给出 ㎡。

## 2. 墙网与门窗洞（推荐数据源：`walls_derived.json`）

- 外轮廓：24 段外墙 + 13 段内墙 = **37 段**，覆盖户型全部边界。
- 高度：默认 2800 mm（与 GLB 顶面一致）；外墙厚度 240 mm，内墙 120 mm。
- 门窗洞：**21 个**（16 门 + 5 窗），全部吸附到最近墙段（snap ≤ 600 mm）；具体属性见 `walls_derived.json#/openings`。
- 房间净区（`walls_derived.json#/rooms`）含 12 个 polygon：与 123kanfang 9 间 + LDK 餐厅派生 + 玄关 + 盥洗 + 过道 子区一致。

> **GLB 直接拆墙段（`walls.json`）只拿到 5 段**：因为 `Section-*` 与 `MergedMesh_*` 都是把多个房间的多面合并到一个 mesh 里；
> 直接拆边界切片极易漏。本目录已改用「房间净区多边形 → 反推墙网」的方法补全。
> 未来如需进一步精修（斜线墙、弧形墙、墙厚分层）可以拿 CAD 叠合校正。

## 4. 三处必须由人工确认的不确定性

1. **储物间/多功能角（6.57 ㎡）的原始户型名** — 123kanfang 把它做成电竞房，与"三室两厅两卫"原始诉求不一致；
   需要现场照片或开发商交房户型图核对。命名 `utility`，备注"待确认"。
2. **主卧进深（4240 vs 4815 mm）** — 用户的尺寸图右侧下方纵向标 4240 mm，但模型与家具摆放都指向 4815 mm（含飘窗位）。
   差额 575 mm 接近飘窗尺寸，请用户复核这是不是测量基准不同（外缘 vs 内缘、飘窗线 vs 主墙）。
3. **次卧／卫生间区分依据** — ViewData 对同名房间未做标签，本档案用面积 + 家具 + 共墙关系判定。
   现场可以靠门牌号或开发商给的"户型册"一次性校准。

## 5. 工具落点与下一步建议

- 把本目录的数据塞进 bear-home（统一技术栈：Taro + React），第一版按"原始测量图"渲一张 SVG：
  1. 用 `walls_derived.json#/walls` 描墙 → 黑实线，240/120 mm 两种粗细。
  2. 用 `walls_derived.json#/openings` 描门窗 → 白色短线（门洞）+ 双线（窗）。`rotation_deg` 决定门扇朝向。
  3. 用 `walls_derived.json#/rooms` 填底色（按用途 token：卧室暖白、卫浴浅冷、厨房略深、客厅留白）。
  4. 尺寸标注：按用户家的尺寸图叠加（用户图的轴线与本档案轴线需在校准后对齐）。
- 3D 模式：直接载入 `floordata0.glb` 当方案对比用；测量模式按交互只显示骨架墙，方案开关控制家具层可见性。
- 一切数据均可在 `derived/*.json` 里直接替换，不需要重解析。

## 6. 数据可信度摘要（用于回看与交接）

| 项 | 准确度 | 说明 |
|---|---|---|
| 外轮廓总尺寸 | ± 20 mm | 三份资料（GLB/208.jpg/用户尺寸图）一致到 1% 内 |
| 房间净面积 | ± 0.5% | ViewData `Area` + shoelace 复算双校验 |
| 房间净 polygon 边线 | ± 30 mm | 与 GLB 自动渲染的墙线 png 吻合率 0.79–1.00 |
| 门窗洞位置 | ± 200 mm | 21 个洞口，按"中心点最近墙段"吸附，多数 ≤ 250 mm |
| 方案家具位置 | ± 50 mm | 136/147 节点落在房间矩形内；其余 11 个为外墙玻璃件 |
| 材质配色 | 色调可参考 | 取的是贴图平均色 / baseColorFactor；不做纹理细节 |
| 房间命名 | 多数 ≤ 推断 ⚠ | 三处需现场确认（见 §4） |
