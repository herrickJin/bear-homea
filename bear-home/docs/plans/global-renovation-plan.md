# 小家 · 两人自用的装修计划与Agent助理

状态：简化设计，尚未实施。更新：2026-10-21。

用户约定：两个人自己用，日常以记录和查看为主；Agent作为装修助理，稳定读取现状、整理计划、记录进展、提供下一步建议。本稿替换上一版偏项目管理的设计。

## 1. 页面只保留三块

首页仍叫“小家”，展示：

1. 当前阶段：例如“方案准备”，手动或通过Agent调整。
2. 接下来做什么：最多3项重点任务，可自己置顶或让Agent整理。
3. 装修主线：按阶段折叠的任务清单；当前阶段展开，后续阶段可随时查看。

页内有“记一笔”和“问问小熊”入口。任务点开后查看备注、修改状态、填写可选日期或关联已有笔记/选购项。

```text
小家                          问问小熊
当前阶段：方案准备

接下来做什么
□ 确认平面布局
□ 跟B确认7万元包含范围
□ 确认中央空调方案

装修主线
▾ 方案准备
  □ 确认平面布局
  ◉ 核对装修报价                  进行中
  □ 确认施工方与合同
▸ 开工与拆改
▸ 水电与设备
▸ 防水与贴砖
▸ 吊顶与墙面
▸ 安装与调试
▸ 验收与入住

                         ＋ 记一笔
```

不设独立的驾驶舱、依赖关系编辑器、完成门、全屋百分比、甘特图、成员权限或自动排期。关键先后关系写进任务备注，Agent给提醒，不用系统锁住操作。

## 2. 简单的数据就够用

一个家的计划 = 当前阶段 + 阶段列表 + 任务 + 进展备注。

任务日常显示字段：

| 字段 | 说明 |
| --- | --- |
| 内容 | 必填，例如“确认厨房水电点位” |
| 阶段 | 放在哪一阶段，可改 |
| 状态 | 待办、进行中、已完成 |
| 备注 | 已知结论、要问的问题、注意事项，均可选 |
| 日期 | 可空；明确约了哪天再填，不要求先做整套排期 |
| 重点 | 是否展示在首页“接下来做什么” |
| 关联资料 | 可选关联现有笔记、准备项或候选，不再复制一份商品记录 |

系统内部另存稳定ID、更新时间、revision及简短修改记录；这些不增加日常填写负担。首版不要求填写负责人；两人需要时写一句备注即可。

记进展时可以直接在对应任务追加一句话，例如“10月21日，B答应多拆不加钱，材料清单待发”。不强迫每条记录都变成一个待办；不知归到哪里时可先存项目备注，之后由人或Agent整理。

不需要的任务可以归档，保留恢复入口；不再设计单独的不适用审批。完成可以重新打开，保留最近修改记录。

## 3. 主线只是起步模板

| 阶段 | 起步任务示例 |
| --- | --- |
| 方案准备 | 整理需求和总预算；确认平面布局；确认设备方案；核对报价与材料；确认施工方和合同 |
| 开工与拆改 | 办理物业手续；现场交底；确认拆改范围；记录拆后情况与修补 |
| 水电与设备 | 确认家具家电和橱柜点位；协调空调等设备；完成水电施工；记录水电验收和管线照片 |
| 防水与贴砖 | 确认防水、回填及瓷砖辅料；记录闭水检查；确认铺砖排版；检查贴砖和排水 |
| 吊顶与墙面 | 确认天花和加固；协调灯位与风口；检查吊顶；确认墙面工艺与色板；检查墙面 |
| 安装与调试 | 安排复尺和商家进场；安装门柜、灯具、卫浴等；设备调试；记录问题与修补 |
| 验收与入住 | 整理整改；核对结算；收齐保修资料；保洁和家具进场；确认入住准备 |

先提供少量任务，可随时增删改。可选设备按实际需要再补，不预生成上百条任务。所有真实状态和时间由用户提供，不从报价或候选数量推断已经完成。

采购提前事项用备注提示，比如“橱柜方案、洗碗机尺寸需在水电定位前确认”。需要跟进时建立一个普通任务，关联现有准备项即可。

## 4. Agent是助理，直接服务记录和查看

| 你说的话 | 助理做什么 |
| --- | --- |
| “我们现在该做什么？” | 读取最新计划、相关选购和笔记，建议最值得推进的几件事，说明理由 |
| “帮我把前期准备理一下。” | 基于现状给出一小份任务草案；整体替换前先展示改动，不清空已有记录 |
| “帮我记一下，周六去确认橱柜方案。” | 新增或更新对应任务，日期可确定时写入，保存后说明记在哪里 |
| “B说多拆不加钱，材料都是一二线。” | 在报价任务追加商家承诺记录，来源注明用户转述，保留材料型号仍待确认 |
| “平面图已经确认了，标记完成。” | 找到对应任务并标记完成，相关备注可同时更新 |
| “空调还没定，帮我把这个任务恢复。” | 重开对应任务；不需要用户再操作一遍表单 |
| “这周做了什么？” | 根据实际修改和进展记录总结，不把计划当作已执行事实 |
| “这篇笔记放到水电任务下。” | 关联已有笔记，不复制全文、不新建同名笔记 |

明确的记录、修改和标记请求直接处理，不为每次普通写入弹确认。只是询问或讨论时给建议，不擅自标记完成；批量重排、批量删除或整体改写先给出拟改内容。找不到唯一任务时再问一句，避免记错。

施工验收结果由你们或现场人员提供，Agent可如实记录“用户说已通过”，不凭照片或建议宣布现场验收合格。提醒先在页面及对话中提供；不默认外发消息或创建定时通知。

## 5. 稳定接入比复杂界面更重要

页面和Agent读写服务端同一份计划。Agent的聊天记忆不作为项目事实库。

现有代码基础：

- home还没有业务内容，可直接在Screen内加入规划页面。
- 装修准备和笔记已存在，保留各自数据；任务可引用其ID。
- 服务端已有App聊天工具与MCP两个入口，但当前工具覆盖不一致：App聊天主要围绕preparation_state与links，MCP仍有旧entries工具。
- 因此“接入Agent”必须同时对齐App工具和MCP，不只写一段提示词，也不把旧entries误认作页面已有任务。

首版只需一份独立计划状态、一个公共读写服务，供页面API、App内Agent、外部MCP Agent共用。工具能力收敛成两类：

1. 读取计划：返回当前阶段、稳定任务ID、状态、重点及相关记录；详情按需读取。
2. 修改计划：按任务/备注ID执行新增、编辑、改状态、归档、关联或调整当前阶段等小范围操作，返回实际保存结果。

接口名称实现时再定，不需要为每一种口语需求增加一套工具。AI所有成功修改回传“plan已变更”，页面刷新对应数据；MCP等外部修改在页面重新进入/回到前台时重新读取，提供手动刷新，不首发实时推送系统。

必须保留的稳定性处理：

- 两人和Agent都可能修改，保存带revision；冲突时保留草稿，重新读取后只处理原本要改的那几项，不用旧整份计划覆盖新数据。
- 新增任务/备注带请求标识，重试不产生重复记录。
- 记录修改来源（页面/App Agent/MCP Agent），提供最近改动和恢复操作；撤销只针对对应改动，不能覆盖其后别人的编辑。
- Agent仅在工具实际保存成功后说“已记下”；失败明确显示未保存，不把聊天文本当成功落库。
- 读取失败显示“暂时读不到计划”，不能伪装成“暂无任务”；离线草稿说明未同步。
- 关联失效显示原项不可用，任务备注仍然保留；商品已买不自动标施工任务完成。

这些是内部稳定性要求，日常界面仍然只是查看、记录和改状态。

## 6. 第一版就做一个完整小闭环

范围：7段主线、普通任务、进展备注、首页重点、可选日期、服务器持久化，以及Agent通过共享服务读写同一计划。

已有商品/笔记关联可逐步补齐，不把自动排程、智能催办、长对话界面改造作为第一版前置。网站保留“问问小熊”轻入口；App通用聊天UI目前仍需补接，外部Agent可先通过MCP使用同一份数据，不假设所有聊天入口都已可用。

第一版验收按真实使用场景：

1. 你记下一项任务，另一人刷新后看得到。
2. Agent读取到的任务、状态和备注与页面一致。
3. 你让Agent记一笔或改状态，工具成功后页面能看到。
4. 两人或Agent同时改，不丢另一方内容；重复请求不重复创建。
5. Agent回答“下一步做什么”依据当前数据，不把建议说成已安排或已验收。

首批真实计划从“方案准备”草案开始，当前阶段仍让用户确认；已知B原工程直接费73,163.42元、整单价70,000元及商家承诺可以记入任务备注，不能据此标记B已签约。
