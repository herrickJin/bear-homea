# 04 · 方案库（小红书收藏 · 剪贴簿）

**状态**：📋 方案定稿（2026-10-10）· 待开工

## 需求原文

1. 经常在小红书刷装修方案，需要把看到的**记录下来**，以后和设计师讨论时能**准确找到**相关方案
2. 有些方案不是全屋的，要支持按**具体位置**收集（阳台、厨房、客厅、吊顶等），支持**归纳分类**

## 概念与核心决策

**方案库 = 给设计师看的剪贴手册**（贴合 App「木作暖光的施工手册」视觉方向）。

| # | 决策 | 理由 |
|---|------|------|
| D1 | 独立第 5 个 tab，命名「**方案**」（位序：小家/方案/记录/预算/我的） | 这是与设计师协作的主工作流，值得一级入口 |
| D2 | 检索主轴 = **空间分页签**（不是筛选 chips、不是搜索框） | 讨论场景是"来，看客厅的"——按空间翻 |
| D3 | 分类为**多标签**（一条方案可挂多个：厨房+吊顶） | 「厨房吊顶」天然跨类；单选是它的子集 |
| D4 | **用户备注 = 卡片标题位**，抓取标题只是补充 | 抓取会失败，用户自己的话不会 |
| D5 | **封面后补 + 分享文本解析**：保存时本地解析真实分享文本（提取规范链接与【】标题，标题免抓取直接可用）；判重按去参后路径；卡片无内容时显示「待整理的方案」占位 | 真实分享文本直接存会报格式错误；同篇不同 xsec_token 会重复；首版四步弹层被反馈过于复杂 |
| D5b | **轻量截图**：分享出去是图片时，存相册后弹层「截图」按钮贴上（`/api/uploads`）；不占表单版面 | 图片分享无法从链接获取，截图是最自然的载体；曾因复杂度移除，随真实需求回归 |
| D6 | 保存极简：文本必填，归类可跳过，要点/截图后补 | 快存慢补，降低收藏摩擦 |

三条洞察（设计的出发点）：
- 检索的第一轴是空间，搜索是辅助
- 用户的话比机器抓的标题可靠
- 小红书场景下用户本来就顺手截屏

## 界面设计

### 界面一 · 方案页（主界面）

```
[胶带]方案库                        ● + 收藏
和设计师讨论的底气，都收在这
─────────────────────────────────
⟨全部⟩ [客厅] [厨房] [阳台] [吊顶] [收纳] ⟩ +管理
│      空间分页签（横滑·一级结构）        │
🔍 搜要点…                     （弱化辅助，一行）
─────────────────────────────────
┌────────┬─────────────────────┐
│ 截图    │ 厨房吊柜无把手做法        │  备注=标题位（2 行截断）
│ 96px   │ ⌗厨房 ⌗吊顶             │  多标签 chips（苔绿 soft）
│        │ xiaohongshu · 10.12   │  mono 数据行 + 状态点
└────────┴─────────────────────┘
┌─────────────────────────────┐
│ ▓小红书  悬浮岛台底部留空做法        │  无截图：域名色块占位
└─────────────────────────────┘
```

- 分页签选中态：苔绿底白字（与导航 active 同语言）；「全部」在最前；胶带只留页眉不扩散
- 状态点（弱展示）：`pending`「待补全」/ `failed`「未抓摘要·链接可用」/ `done` 无标
- 空态：小熊 + 「还空着」+ 主按钮「收藏第一个方案」+ 一行教学「小红书 分享→复制链接→回到这里」
- 桌面端：侧栏加「方案」，卡片双列网格

### 界面二 · 收藏弹层「对家的想法」（v3 · Apple 式底部弹层）

```
手机：底部升起的大圆角弹层        桌面：居中卡（轻缩放入场）
┌──────────────────────┐
│ 对家的想法              × │   打开即读剪贴板：是链接就静默填好
│ [粘贴小红书链接____] [粘贴] │   （读不到则手动粘贴；非法/重复即时提示）
│ 归类 · 可跳过               │
│ (⌗全屋)(⌗客厅)(⌗厨房)→ 横滑  │   多选；新建只在「分类管理」
│ [        收藏        ]      │   成功：轻震动 + toast「收进方案库」
└──────────────────────┘   底部贴合 safe-area
```

- 进出同路径（升起/落回，250ms ease-out）；`prefers-reduced-motion` 退化为淡入淡出
- 要点与截图不在保存时收集：详情页「编辑」随时补；截图上传整体后置
- 新卡片无备注时显示「待整理的方案」占位标题；重复 URL toast「已收藏过」

## 数据模型（server/）

```sql
-- 迁移（注意：SQLite ALTER TABLE 无 IF NOT EXISTS，需 pragma 检查或捕获 duplicate column 实现幂等）
ALTER TABLE links ADD COLUMN note TEXT;                    -- 用户要点备注
ALTER TABLE links ADD COLUMN category_ids TEXT NOT NULL DEFAULT '[]';  -- JSON 数组，存分类 id
ALTER TABLE links ADD COLUMN shot_url TEXT;                -- 用户截图（与 Agent 的 cover_url 分离，展示优先级更高）

CREATE TABLE IF NOT EXISTS categories (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  sort INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);
-- 预置分类 INSERT OR IGNORE（稳定 id：cat-preset-*）：全屋/客厅/厨房/卧室/卫生间/阳台/吊顶/收纳
```

展示优先级：`shot_url > cover_url > 域名色块`；用户截图与 Agent 抓取互不覆盖。

## API 变更（server/）

| 端点 | 变更 |
|------|------|
| `GET /api/categories` | 新增：按 sort 返回全部分类 |
| `POST /api/categories` | 新增 `{name}`；重名 409 |
| `PATCH /api/categories/:id` | 新增 `{name?, sort?}` |
| `DELETE /api/categories/:id` | 新增：同时从所有 links.category_ids 中剥离该 id |
| `POST /api/links` | 扩展：接受可选 `note` / `category_ids`（校验为 id 数组）；去重逻辑不变 |
| `PATCH /api/links/:id` | 扩展：支持 `note` / `category_ids`（现有 title/summary/cover/status 逻辑不变） |
| `GET /api/links` | 扩展：`?tag=<categoryId>`、`?q=<关键词>`（LIKE 匹配 note/title/summary）；`category_ids` 为 JSON 需在路由内解析过滤（单用户小数据量，可接受） |
| MCP `save_link`/`update_link` | 透传 `note`/`category_ids`，Agent 后续可代为归类补摘要 |

## 边界与注意

- **去重**：同 URL 已存在且非 failed → 后端原样返回 `deduplicated:true`，前端 toast「已收藏过」并滚动定位
- **小程序真机图片**：截图存自有服务器 `http://119.27.191.90`，开发者工具（不校验合法域名）可显示；**真机需等 HTTPS/备案域名**，期间真机显示域名色块兜底
- **H5 打开原文**：直接 `<a>` 新窗口；小程序无法跳外部 App → 主按钮为「复制链接」
- **failed 不是死链**：链接和备注永远可用，仅提示"未抓到摘要"
- **分类删除**：links 上该标签同步剥离（确认弹层说明"方案本身保留"）

## v5.2 增补（2026-10-12，工具栏对齐小红书搜索页）

| 项 | 设计 |
|----|------|
| **搜索独立置顶** | 搜索框独立整行（44px、`--r-lg`、井底实底、静息无边框、镜标右端），分类标签行移到其下；桌面不再「页签 + 280px 搜索」同行。手机吸顶 = 搜索 + 标签整体。规范见 DESIGN.md 十一.9 |

| ⚠️ 坑 1 | Taro H5 Button（shadow DOM 宿主）的 `::before/::after` 伪元素不渲染/被吞——渐变遮罩必须挂在 View 容器伪元素上 |
| ⚠️ 坑 2 | flex 行锁高做动画时 `align-items` 默认 stretch 会把子项拉成容器高——「单行高度」测量值失真（80 而非 36），必须 `align-items: flex-start` |
| ⚠️ 坑 3 | 容器伪元素树序在子元素之后绘制，会盖住绝对定位的展开钮——按钮需 `z-index: 1` |
| ⚠️ 坑 4 | 小程序无 `window.matchMedia`，CategoryTabs 的溢出测量需先判存在，否则 weapp 端抛错 |

## 验收标准

1. 从「复制小红书链接」到卡片出现在列表 ≤ 3 步操作
2. 按空间分页签浏览 + 搜索备注，均能命中目标卡片（模拟设计师讨论场景）
3. 一条方案可挂多个分类；新建/改名/删除分类后卡片同步正确
4. 带截图的卡片在小程序（开发者工具）与 H5 均正常显示
5. 重复保存同链接有明确提示且不产生重复卡片
6. 无 Agent 时页面完整可用（failed/pending 状态展示正常）
7. 全部样式消费 token；typecheck/build 双端通过
