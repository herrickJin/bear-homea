# 选购后端接入（2026-10-14）

当前 UI 使用 `/api/preparation` 聚合接口：GET 返回 `{revision, data, updatedAt}`；PUT 接收 `{revision, data}`。data 完整包含 items、records、skipped、associations、appliedImports。所有操作在 SQLite preparation_state 中原子保存，沿用现有 Bearer 鉴权；不与旧 entries 装修日志混用。

当前产品单个共享家庭，聚合存储避免候选、封面排序、笔记关联部分更新。它不是独立候选 CRUD 或多账户模型；后续规模增长可在保持接口兼容的情况下拆表。GET `/api/rooms` 提供固定房间与笔记标签映射，主卧/次卧兼容旧「卧室」标签。当前前端房间目录仍为固定配置。

PUT 必须携带读取时的 revision，成功后版本 +1；版本不符返回 409，不覆盖服务器。服务端校验字段、非负价格、多图最多 9 张、准备项房间归属、单项已选定唯一、笔记关联范围。删除准备项后，候选可保留原 itemId 成为未归类记录，与当前 UI 一致；笔记引用不删除笔记文件。

前端首次打开先 GET；服务器有记录时使用服务器数据，没有记录则直接显示空候选与基础房间/准备项目录。没有导入入口，不自动迁移旧本地记录或注入示例候选。

后续变更串行同步，每次修改先保存 pending 草稿与对应版本，成功后才清除；关闭页面再进入时，同版本草稿继续提交，服务器版本已变化则保留草稿并提示冲突。失败保留设备草稿并显示重试；冲突时保存在 bear-home-preparation-v1-unsynced-backup 后重新加载，避免覆盖另一台设备。本地缓存用于保留草稿，不在网络错误时充当已同步数据。

当前同步需要打开/刷新页面读取最新服务器内容，没有实时推送。超时后若请求已在服务器成功，重试可能触发版本冲突；重新加载可恢复服务端已保存内容，操作不重复建候选。图片仍复用 uploads/files 服务，移除候选图片仅删除引用；暂不自动清理文件，避免误删笔记共享资源。

手动待确认事项、商品抓取分析、图片 OCR 并非当前 UI 已有功能，仍属于下一阶段。本批 AI 文字整理确认后的保存已复用选购持久化。

验证：前后端 TypeScript；小程序构建；隔离 SQLite 路由测试覆盖初次加载、完整往返保存、版本冲突拒绝、非法价格/房间/多图/重复选定拒绝及删除准备项保留候选。线上 health、preparation、rooms 均返回 200。浏览器已验证导入、选定/已买状态同步及刷新恢复。测试中隔离转发最初未生效，曾在原为空的正式选购库写入示例快照；在版本仍为 1 且内容与测试数据完全一致的事务条件下，先备份快照再移除，正式库恢复 revision=0/data=null，笔记和文件未修改。随后使用隔离数据库完成状态与刷新验证。
