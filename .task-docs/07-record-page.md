# 07 · 记录页（选购台账）

**状态**：🚧 进行中（2026-10-12 立项；本任务只做页面第一版，服务端后置为任务 08）

## 需求原文

1. 家电对比记录：统计所有家电看的数据（京东、线下等等渠道），方便后续参考**要买什么家电、买哪一家、去哪里买、价钱是什么**
2. 装修相关的材料记录：材料类型、价钱、品牌等

## 概念与核心决策

**记录页 = 选购比价台账**：品类 → 看过的每一款（名称/价格/渠道）→ 比完做决策。
与「笔记」的分工：笔记是给设计师看的素材库（向外的），台账是给自己看的购物决策账本（向内的）。记账归「预算」tab，不在这。

| # | 决策 | 理由 |
|---|------|------|
| D1 | 第 3 个 tab「记录」，页面名「**选购台账**」；页内一级切换 = **家电 / 材料** | 比价不跨类发生；两类分开，各自有品类体系。导航仍 5 项不膨胀 |
| D2 | 检索主轴 = **品类**（家电：空调/冰箱/…；材料：瓷砖/地板/…），对应笔记页的空间页签 | 对比发生在品类内：不会拿空调和瓷砖比 |
| D3 | **一行 = 一次看到的报价**：同一款产品多个渠道 = 多行，**不判重** | 与笔记相反；重复恰恰是比价的素材（京东价 vs 线下价） |
| D4 | **状态四值**：在看 looking / 候选 shortlist / 已买 bought / 放弃 dropped | 台账的终点是决策；「交定金 vs 付全款」暂不分，后续可加「已定」 |
| D5 | **快存慢补**：记一笔 = 品类（必选）+ 名称（必填），价格/渠道/备注可选 | 逛店的间隙 10 秒记完；笔记同款哲学 |
| D6 | 品类 = 预置常量 + 自定义输入（**不建 categories 表、不做管理弹层**） | 品类少而稳定，自由文本够用；需要时再升级 |
| D7 | **第一版无照片**（报价单/发票截图随服务端 uploads 一起做） | mock 存临时路径刷新即失效，先不做假能力 |
| D8 | 服务端未建前，数据存 **Taro storage**（本地持久化），示例数据首启播种 | 刷新不丢，页面可先当真台账用；接 API 时换 service 层 |

```

┌───────────┬───────────┐

⟨全部⟩ [空调] [冰箱] [洗衣机] ⟩    ← 品类 chips（复用 cat-tab，无「＋管理」）
─────────────────────────────────
共 12 条 · 已买 3            按价格↑    ← 汇总行 + 排序切换（mono）
空调 · 5 款 · ¥4,899–6,100 · 已买 1  ← 品类小结（组头）
┌──────────────────────────────┐
│ 格力 云逸-II 1.5匹       ¥5,699 │  名称（500）+ 价格（mono，右对齐）
│ ●已买   京东 · 10.12            │  状态点 + 渠道 · 日期（mono）
│ 新一级能效，含基础安装           │  备注（有则一行截断）
└──────────────────────────────┘
```

- 品类分组展示：「全部」= 按品类分节（预置序在前，自定义品类按最近使用排后）；选中某品类 = 只看该节
- 节内排序：默认**价格升序**（无价的沉底），可切**最近记录**；这是比价的阅读顺序
- 桌面：列表限宽 760px 居中（台账是线性文档，不做多列网格）
- 空态：小熊 + 「台账还空着」+ 主按钮「记第一笔」+ 一句「逛到的型号、报价，随手记下来」
- 手机：切换/搜索/品类三行整体吸顶（同笔记 insp-toolbar 模式）

## 数据模型（server/ · 任务 08 实现，此处定稿）

```sql
CREATE TABLE IF NOT EXISTS items (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL DEFAULT 'appliance'
    CHECK (kind IN ('appliance', 'material')),
  category TEXT NOT NULL,             -- 品类（自由文本，预置见下）
  name TEXT NOT NULL,                 -- 品牌 + 型号
  price REAL,                         -- 元；空 = 未问价
  channel TEXT,                       -- 渠道（自由文本）
  note TEXT,                          -- 参数、活动、感受
  status TEXT NOT NULL DEFAULT 'looking'
    CHECK (status IN ('looking', 'shortlist', 'bought', 'dropped')),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX items_kind_cat_idx ON items(kind, category);
```

- 照片（报价单/发票）：任务 08 加 `photos TEXT NOT NULL DEFAULT '[]'`（uploads 文件 URL 数组）
- API 草案：`GET /api/items?kind=&q=`、`POST /api/items`、`PUT /api/items/:id`（含 status）、`DELETE /api/items/:id`；MCP 透传（create_item / list_items / search_items / update_item）随任务 03 扩展
- 预置品类（前端常量为单一真源，服务端只存字符串）：

## 边界与注意

- **本地持久化的天限**：mock 走 Taro storage，H5 = localStorage、小程序 = 本地缓存；换设备/清缓存即失，服务端落地前别当唯一真源
- **同一款多渠道 = 多行**，这是特性不是脏数据；不加判重提示
- **排序中无价条目**：价格升序时沉到节尾（未问价的也是信息）
- **状态色**：在看=faint / 候选=primary / 已买=success / 放弃=danger，只上在状态点与状态字，不铺卡面（内容卡片区一律中性）
