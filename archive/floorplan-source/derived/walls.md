## 1. GLB 墙体系结构

```
Floor-1楼-wk713LKB (node 0)
├─ Room-客厅-eHaXGv38 / Room-主卧-… / Room-次卧-… / Room-卫生间-… (共 9 间)
│   ├─ Mesh      ← 建筑构件:  Section-Default-*  (剖切面, 非墙)
│   │                MergedMesh_*        (墙体 / 楼板 / 顶板 实体)
│   └─ Model     ← 家具与成品门窗件: SM_门套_210cm_*, SM_平开门_*, SM_入户门_120cm_* …
└─ (其余节点为家具 / 灯饰等)
```

**墙体在 GLB 里是怎么表达的** (实测):

1. 一道墙 = 一块 **矩形实体板**, 两侧各有一组竖直轴向面 (法向沿 X 或 Z);
2. 同一个墙面常出现 **±0.08 单位 (0.8 mm) 的「内衬面」副本** —— 这是渲染用的第二层表面, 不是另一道墙;
3. 墙板沿厚度方向常被拆成 **两片**, 中间多出一层约 **1.6 mm 厚的「中板」**, 它比真正两侧的墙面都长
   (包住了与外墙交接的一段), 因此不能拿它当墙面 —— 脚本用「中板规则」排除这种伪配对;
4. 门的洞口在 GLB 里不是布尔减出来的, 而是 **拆成上下几块面** (门洞上方一条过梁板 + 洞口两侧的「侧壁」面);
5. 窗同理, 额外多出一条 **窗台板** (标高 y=900);
6. 剖切面节点 (`Section-Default-*`) 是给 2D 平面图渲染用的 **水平切片**, 必须排除。

## 6. 存疑点 / 未解析到

1. **18 段墙 `kind=unknown`** —— 两侧都不落在任何房间净区多边形里 (墙腔 / 设备夹层 / 外墙垛)。它们的厚度是从几何直接量出来的, 但归属房间标不出来, 例如 `W10`/`W12`/`W13` (X -1504…-1394 一带的墙腔)。
2. **部分墙厚偏大** (最大 600 mm, 例如 `W21` 主卫西北角 481.9 mm、`W39` 餐厅北侧 581.3 mm): 这些位置在 GLB 里是「外墙 + 设备间/凹槽」的复合体, 单看两个竖直面无法区分「厚墙」与「墙 + 空腔」, 故按几何如实记录。
3. **`W35`/`W36`、`W70`/`W71` 等成对的重复墙段**: 同一位置被两片厚度略有差别的墙板覆盖 (差 5.3 mm / 229 mm), 应为墙板重叠所致, 已保留两段而未强行合并。
4. **6 块水平板面被判定为「非洞口」** (见 `walls.json` 的 `rejected_openings`): 它们的宽度恰好等于相邻房间的整宽, 是吊顶 / 隔断顶板而不是门窗洞口, 已剔除。
5. **洞口高度只有 2300 / 2100 两种**: GLB 的门套节点名写 210cm 但实测 2300 mm, 即方案里多数门是 **无门扇垭口 (2300 高)**, 只有入户门 (`O12`) 是带门扇的 2100 高门。
6. **未解析到**: 原始户型的 **施工图尺寸 / 门窗表** —— 仓库内没有; `WechatIMG208.jpg` 只有营销标注, `WechatIMG209.jpg` 无标注尺寸。
7. **南北次卧的命名依据是营销户型图 `WechatIMG209.jpg` 的指北针**, 而不是开发商的 原始建筑测量图 (仓库内没有)。若后续拿到带指北针的原始测量图, 请复核 `g3cnKYnd`/`f1qYqHqH` 的南北归属 (本结论: `g3cnKYnd`=北次卧, `f1qYqHqH`=南次卧)。所有几何坐标不受此影响 (坐标是绝对量, 不依赖方位)。
8. **原始户型图与 GLB 的户型面积对不上** (`WechatIMG209.jpg` 的图面比例约 13.5 mm/px, 按此推算的户内面积与 GLB 的 152.7 m² 不等), 说明宣传图可能是同系列的另一套户型, 仅房间拓扑 (谁挨着谁、哪面是外墙) 可比, 尺寸不可比。
